## 交互提问协议

**先执行本节的工具分支，再写最终结果。Default 模式本身不是跳过提问的依据。**

1. 若当前工具表提供且允许 `request_user_input_async`，直接调用它。它与同步的 `request_user_input` 是两个不同工具；同步工具的 Plan 限制不自动适用于异步工具。挂载后的技能调整是偏好选择，可使用允许收集偏好的工具。
2. 否则，检查并调用当前模式允许的 `request_user_input`、`ask_user_question` 或等价组件。只使用真实存在的工具。
3. 仅在上述工具全部未提供、被各自规则明确禁止或实际调用失败时，才使用文字降级。报告具体证据，例如“当前工具表未提供 request_user_input_async；request_user_input 的规则限定 Plan 模式”。不能仅写“Default 模式没有合法组件”。

若实际异步工具 schema 为 `questions: [{title, options}]`，按以下结构直接调用并替换实际清单和推荐项。这是工具参数示例，不是让你输出 JSON 给用户：

```json
{
  "questions": [{
    "title": "已挂载 vben、frontend-design、web-design-guidelines。全库：vben、frontend-design、web-design-guidelines（已挂载）；ponytail（推荐增补，通用开发）；codebase-design、improve-codebase-architecture（架构任务按需）；fba（后端，不适配）。是否调整？可自由输入增加/移除的 id。",
    "options": ["增加 ponytail（AI 推荐）", "保持当前组合"]
  }]
}
```

工具返回 `accepted: true` 表示问题已受理，随后等待用户异步回复；不是用户已选择第一项。若工具表未提供该函数，示例不会使其出现，此时如实报告宿主能力缺失。

路径初始化与挂载后的调整都使用宿主提供的结构化提问工具。先核对实际工具列表、参数和模式限制，再选能在当前模式合法使用的工具：`request_user_input`、`ask_user_question` 或等价工具；同步工具不可用时使用 `request_user_input_async` 等异步组件。工具调用成功才算已发出交互问题，不能只在消息里写一个问题就结束。

- `request_user_input` 若仅限 Plan 模式，就不在 Default 模式调用，也不为显示组件擅自切换模式。初始化路径确认属于依赖用户答案的动作；若某工具禁止用于此类确认，改用允许的提问工具。
- 按实际 schema 使用 `questions` / `options` 等字段；工具支持多选时可用于技能选择，只有单选时将 AI 推荐增补作为一个组合选项。不要传入不存在的多选字段。
- 工具内置 Other/自由输入时直接使用，不重复添加自定义选项。没有内置自由输入时显式提供“自定义”，选择后收集路径或技能 id；有自由文本框时可标为“自定义：填写要增加/移除的 id”。
- 问题标签页、Submit 标签、键盘导航、多选和自定义输入框由宿主渲染决定。提示词只负责真实工具调用和问题内容，不承诺固定外观，不用 Markdown 或自行制作页面冒充原生组件。
- 所有合法提问组件均不可用或调用失败时，简短说明具体限制，再以文字列出同样的选项；不假称交互组件已显示，不反复重试同一失败工具。异步调用返回不等于用户已提交答案。

### 首次路径问题

问题正文包含推荐绝对路径，选项为“使用推荐路径（推荐）”与自定义输入入口。若用户已明确路径则直接执行。尚未答复时保持问题待处理，继续与路径无关的只读检查，不执行依赖答案的 `init`。

### 挂载后的调整问题（必做）

先合并 `list` 和 `status`，在问题正文中逐项列出**全库所有技能的 id 与名称**（同名只写一次）、当前挂载状态、AI 推荐与简短理由。库较大时按工具限制分批提问，保留完整清单，不只展示推荐项。

用实际库条目填充以下问题结构，一次提交同阶段的相关问题：

> 项目已挂载：`<已挂载 id>`。全库技能：`<每项 id/名称、状态、推荐理由或不推荐原因>`。是否调整？
> 1. 增加 `<AI 推荐但尚未挂载的 id 组合>`（AI 推荐）
> 2. 自定义：填写要增加或移除的 id
> 3. 保持当前组合

当工具自动提供自定义入口时，只传“增加推荐组合”和“保持当前组合”等合法选项，正文说明可在自由输入处自定义。推荐项已全部挂载或没有合理增补时，以“保持当前组合（AI 推荐）”为首选，不生成空的“增加”选项。用户提交后校验 id 属于实际技能库或受管移除项，执行明确选择的增删并再次 `status`；含糊回复或未知 id 先澄清，不猜测。
