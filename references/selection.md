## 技能选择：初始化覆盖项目，任务执行按需加载

- **项目初始化**（“初始化项目 skills”“给项目配置技能”）：目标是准备项目日常开发所需的技能组合。逐项检查库中全部技能，覆盖适配的框架开发、界面设计、UI/可访问性检查等前端能力；将库中所有适配该前端技术栈且不冲突的前端技能加入默认组合。不要以“这次还没设计页面/审查 UI”为由漏挂这些前端技能。后端或全栈项目同样按实际技术栈覆盖相应能力。
- **单次任务**（修一个 bug、改一个页面）：按具体任务选择需要的技能，复用已挂载项；不自动卸载本次未使用的技能。
- **挂载与调用分开**：初始化可以挂载设计与审查技能，执行任务时仅加载和调用当前阶段适用的指引；挂载审查/架构技能不等于立即开展审查、重构或追问。
- **通用技能**：开发习惯、模块设计、架构分析等按描述给出增补推荐和理由，不因属于代码技能就全部挂载。不匹配技术栈的技能列入全库清单并解释不推荐原因。
- **动态选择**：以本次 `list` 的真实条目为准。示例：库中存在 `vben`、`frontend-design`、`web-design-guidelines` 且项目确认为 Vben 前端时，初始化默认包含这三项；`ponytail` 可作为通用开发增补推荐；`fba` 不因项目有 API 请求就视为适配。示例名称不是固定依赖。

## 操作流程

1. **确认项目。** 根据用户目标和工作目录确定项目；不明确时询问路径，不把临时目录当作项目。纯问答、软件安装、文档和图片任务无需挂载。
2. **发现与完整匹配。** 执行 `list`，结合项目清单、README 和目录结构，逐项评估全部技能的 `description`。按本文区分项目初始化与单次任务，不在找到首个框架技能后停止，不设 1–3 个的硬上限；无匹配项就说明情况，不凭名字推断，不默认 `--all`。
3. **核对并挂载。** 先 `status`，已为 `mounted` 的无需重复操作。使用 `list.skills[].id` 作为 `--skills` 的值；`name` 是 frontmatter 名称，可能与目录名不同。遵守项目已有的确认要求。
4. **验证与加载。** 再执行 `status`，确认目标项目及技能状态。读取选中技能的 `path/SKILL.md` 后才能声称已加载指引。目录挂载不代表 Codex 清单已刷新；未刷新时建议新开目标项目会话。
5. **发出调整选择。** 首次项目初始化、用户要求重新配置或技术栈变化时，验证后必须按 [交互提问协议](interaction.md) 调用可用的交互提问组件，展示全库与推荐增补。发出问题后才报告初始化结果，注明调整是否待回复；普通汇报不能替代此步骤。用户未回复时保留已验证的默认组合，不执行待确认的增删；项目和需求未变时不反复提问。
